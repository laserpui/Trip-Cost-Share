# Trip Cost Share v5.1

> แก้ไขปัญหาวันที่ในช่อง “วันที่เข้าร่วม” และ “คืนที่พัก” เลื่อนย้อนหลัง 1 วัน เนื่องจากการแปลง Local Time เป็น UTC ผ่าน `toISOString()` โดยระบบ v5.1 คำนวณวันที่แบบ Date-only และยึดเขตเวลา Asia/Bangkok


ระบบบันทึกใบเสร็จและแบ่งค่าใช้จ่ายสำหรับกิจกรรมหลายวัน โดยใช้:

- GitHub Pages เป็นหน้าเว็บไซต์
- Google Sheet เป็นฐานข้อมูล
- Google Apps Script Web App เป็น API
- Google Drive สำหรับเก็บรูปใบเสร็จ

## สิ่งที่เปลี่ยนจาก v4

v5 เปลี่ยนจากการหารค่าใช้จ่ายด้วยสูตรกว้าง ๆ เป็นโครงสร้างดังนี้:

```text
ใบเสร็จ
 ├─ ผู้สำรองจ่าย 1 คนหรือหลายคน
 ├─ รายการย่อย 1 รายการหรือหลายรายการ
 │   ├─ หมวด
 │   ├─ วิธีหาร
 │   ├─ ผู้ร่วมรับผิดชอบ
 │   └─ ผลแบ่งรายบุคคล
 └─ รูปใบเสร็จ
```

ผลแบ่งของแต่ละรายการจะถูกบันทึกลงชีต `ExpenseShares` จึงไม่เปลี่ยนตามข้อมูลสมาชิกในภายหลังโดยอัตโนมัติ หากต้องการคำนวณใหม่ ให้เปิดใบเสร็จจากหน้าหลังบ้านแล้วบันทึกอีกครั้ง

---

## วิธีหารที่รองรับ

### 1. ผู้ที่มาในวันที่ใบเสร็จ

เหมาะกับค่าอาหารและเครื่องดื่มรายวัน ระบบเลือกผู้ที่มีวันเข้าร่วมตรงกับวันที่ใบเสร็จเป็นค่าเริ่มต้น และผู้ใช้สามารถปรับรายชื่อได้

### 2. ผู้ที่พักในคืนที่เลือก

เหมาะกับโรงแรม บ้านพัก และค่าใช้จ่ายรายคืน โดยแยก “วันที่เข้าร่วม” ออกจาก “คืนที่พัก”

### 3. เลือกคนแล้วหารเท่ากัน

เหมาะกับกิจกรรม ค่าเรือ ค่าดำน้ำ ค่าเข้าชม หรือค่าใช้จ่ายที่มีเฉพาะบางคน

### 4. ตามจำนวนคน-วัน

เหมาะกับของใช้ส่วนกลาง ค่าเช่ารถ หรือค่าใช้จ่ายที่ใช้ตลอดกิจกรรม คนที่อยู่ 2 วันจะมีน้ำหนัก 2 หน่วย และคนที่อยู่ 1 วันมีน้ำหนัก 1 หน่วย

### 5. ตามหน่วยหรือน้ำหนัก

สามารถระบุน้ำหนักรายคน เช่น:

- ผู้ใหญ่ 1 หน่วย
- เด็ก 0.5 หน่วย
- ห้องเดี่ยว 2 หน่วย
- จำนวนแก้วหรือจำนวนรายการที่สั่ง

### 6. ระบุยอดต่อคน

กรอกจำนวนเงินที่แต่ละคนรับผิดชอบโดยตรง ระบบจะตรวจว่ายอดรวมตรงกับยอดรายการย่อย

### 7. ทุกคนเท่ากัน

ใช้สำหรับค่าจองหรือค่าใช้จ่ายที่กลุ่มตกลงหารทุกคนเท่ากัน

## การปัดเศษ

ระบบคำนวณเป็นหน่วยสตางค์และกระจายเศษด้วยวิธี Largest Remainder

ตัวอย่าง 1,000 บาท หาร 3 คน:

- คนที่ 1 = 333.34 บาท
- คนที่ 2 = 333.33 บาท
- คนที่ 3 = 333.33 บาท

ยอดรวมจึงกลับมาเท่ากับ 1,000 บาทพอดี

---

## การชำระคืน

รายการโอนเงินระหว่างสมาชิกถูกแยกออกจากค่าใช้จ่าย เพื่อไม่ให้ยอดค่าใช้จ่ายรวมเพิ่มซ้ำ

สรุปรายบุคคลประกอบด้วย:

- ยอดที่ต้องรับผิดชอบ
- ยอดที่สำรองจ่ายให้ร้านค้า
- ยอดที่โอนคืนให้สมาชิกแล้ว
- ยอดที่ได้รับคืนแล้ว
- ยอดคงเหลือ

ระบบสร้างคำแนะนำการโอนเพื่อปิดยอด โดยจับคู่ผู้ที่ต้องจ่ายเพิ่มกับผู้ที่ควรได้รับคืน

## Google Sheet ที่ระบบสร้าง

| Settings | ชื่อกิจกรรม ช่วงวันที่ และสถานะเปิด/ปิด |

| AdminLog | ประวัติการเพิ่ม แก้ไข ลบ และย้ายข้อมูล |

# การอัปเกรดจาก v4

## สำคัญ: สำรองข้อมูลก่อน

ก่อนดำเนินการ ให้สร้างสำเนา Google Sheet เดิมไว้หนึ่งชุด

## ขั้นตอน

1. นำไฟล์ทั้งหมดใน v5 อัปโหลดขึ้น GitHub แทนไฟล์เดิม
2. เปิด Google Sheet เดิม
3. ไปที่ `Extensions > Apps Script`
4. แทนที่โค้ดเดิมด้วยไฟล์ `apps-script/Code.gs`
5. กด Save
6. รันฟังก์ชัน `setupDatabase()` หนึ่งครั้ง
7. อนุญาตสิทธิ์ Google Sheet และ Google Drive
8. หากต้องการย้ายค่าใช้จ่ายเดิมจากชีต `Expenses` ให้รัน `migrateV4Data()` **เพียงหนึ่งครั้ง**
9. ตรวจสอบชีต `Receipts`, `ExpenseLines` และ `ExpenseShares`
10. ไปที่ `Deploy > Manage deployments`
11. กด Edit และเลือก `New version`
12. กด Deploy

ระบบจะไม่ลบชีต `Expenses` เดิม เพื่อให้ใช้ตรวจสอบย้อนหลังได้

## หลักการย้ายข้อมูลเดิม

ค่าใช้จ่ายแต่ละรายการของ v4 จะถูกสร้างเป็น:

- ใบเสร็จ 1 ใบ
- รายการย่อย 1 รายการ
- ผู้สำรองจ่ายตามข้อมูลเดิม

การแปลงวิธีหาร:

| v4 | v5 |
|---|---|
| daily | ผู้ที่มาในวันที่ใบเสร็จ |
| attendance_days | ตามจำนวนคน-วัน |
| equal_all | ทุกคนเท่ากัน |

สำหรับรายการแอลกอฮอล์ ระบบจะเลือกเฉพาะสมาชิกที่มีสถานะผู้ดื่มจากข้อมูลเดิม จึงควรตรวจสอบอีกครั้งหลังย้ายข้อมูล

# การติดตั้งใหม่

1. สร้าง Google Sheet ใหม่
2. ไปที่ `Extensions > Apps Script`
3. วางโค้ดจาก `apps-script/Code.gs`
4. รัน `setupDatabase()`
5. เลือก `Deploy > New deployment > Web app`
6. ตั้งค่า:
   - Execute as: Me
   - Who has access: Anyone
7. Deploy และคัดลอก Web App URL
8. เปิด `config.js`
9. ใส่ URL ที่ `API_URL`
10. อัปโหลดไฟล์ทั้งหมดขึ้น GitHub
11. เปิด GitHub Pages ที่ `Settings > Pages`

# หน้าหลังบ้าน

เปิดไฟล์:

```text
admin.html
```

รหัสเริ่มต้น:

```text
Admin1234
```

ระบบตรวจรหัสที่ Google Apps Script และออก Token ชั่วคราวประมาณ 6 ชั่วโมง

## เปลี่ยนรหัส Admin

1. เปิด `Code.gs`
2. ค้นหาฟังก์ชัน `changeAdminPassword()`
3. เปลี่ยนค่า:

```javascript
const newPassword = "CHANGE_ME";
```

เป็นรหัสใหม่ที่มีอย่างน้อย 8 ตัวอักษร

4. รัน `changeAdminPassword()` หนึ่งครั้ง
5. เปลี่ยนค่ากลับเป็น `CHANGE_ME`
6. บันทึกและ Deploy เวอร์ชันใหม่

# การปิดยอดกิจกรรม

หน้าหลังบ้านสามารถเปลี่ยนสถานะเป็น `ปิดยอด/ล็อกกิจกรรม`

ก่อนปิดยอด ระบบตรวจสอบว่า:

- ยอดผู้สำรองจ่ายรวมตรงกับยอดใบเสร็จ
- ยอดรายการย่อยรวมตรงกับยอดใบเสร็จ
- ทุกรายการมีผลการหาร
- ผลการหารรวมตรงกับยอดรายการ
- ไม่อ้างอิงรายชื่อที่ไม่มีอยู่
- รายการชำระคืนมีผู้โอน ผู้รับ และยอดถูกต้อง

เมื่อปิดยอดแล้ว หน้าหลักยังดูและแชร์ข้อมูลได้ แต่ไม่สามารถเพิ่มรายชื่อ ใบเสร็จ หรือรายการชำระคืนใหม่ จนกว่า Admin จะเปิดกิจกรรมอีกครั้ง

# ข้อควรระวัง

- การ Deploy แบบ `Anyone` เหมาะกับกิจกรรมภายในหรือข้อมูลความเสี่ยงต่ำ
- รูปใบเสร็จถูกตั้งให้ผู้ที่มีลิงก์สามารถดูได้ หากนโยบาย Google Workspace ไม่อนุญาต ระบบอาจไม่สามารถเปิดรูปผ่านหน้าเว็บสาธารณะได้
- ควรเปลี่ยนรหัส Admin ก่อนใช้งานจริง
- อย่าเรียก `migrateV4Data()` ซ้ำหลังมีข้อมูลใน `Receipts`
- ก่อนแก้ช่วงวันที่กิจกรรม ควรตรวจวันที่เข้าร่วมและคืนที่พักของสมาชิกเดิม
